# 高级对象


## Proxy / Reflect（对象元编程）

### proxy

Proxy 本质：对象的拦截器

可以拦截对象的各种操作：

- 读取属性
- 设置属性
- 删除属性
- 函数调用
- 构造函数
- in 操作符
- for in 枚举

```javascript
const obj = { a: 1 }

const proxy = new Proxy(obj, {
  get(target, key) {
    console.log('读取属性', key)
    return target[key]
  }
})

proxy.a // 1 读取属性“a”
```

常见拦截方法有：

| trap           | 作用     |
| -------------- | ------ |
| get            | 读取属性   |
| set            | 设置属性   |
| has            | in 操作符 |
| deleteProperty | 删除属性   |
| ownKeys        | 获取 key |
| apply          | 函数调用   |
| construct      | new    |


经典使用场景：Vue3 响应式。

### Reflect

Reflect 是 ES6 新增的 对象操作 API。

它把很多 Object 的操作变成函数式调用。


| Object API            | Reflect                |
| --------------------- | ---------------------- |
| Object.getPrototypeOf | Reflect.getPrototypeOf |
| Object.defineProperty | Reflect.defineProperty |
| in                    | Reflect.has            |
| delete                | Reflect.deleteProperty |


```javascript
const proxy = new Proxy(obj, {
  get(target, key) {
    return Reflect.get(target, key)
  }
})
```

Proxy 是拦截器【】
Reflect 是默认行为【正向操作】

## 浅拷贝 vs 深拷贝

### 浅拷贝

只复制第一层对象。如果里面是引用类型：仍然共享地址。

```javascript
const obj = {
  a: 1,
  b: { c: 2 }
}

const copy = { ...obj }

copy.b.c = 100

console.log(obj.b.c) // 100
```

常见前拷贝方法：

| 方法            | 说明       |
| ------------- | -------- |
| Object.assign | 浅拷贝      |
| 扩展运算符         | {...obj} |
| Array.slice   | 数组       |
| Array.concat  | 数组       |


### 深拷贝

深拷贝：递归复制所有引用对象。

```javascript
JSON.parse(JSON.stringify(obj))
```
不能处理：

- function
- undefined
- Symbol
- Date
- RegExp
- Map
- Set
- 循环引用

浏览器新增API

```javascript
structuredClone(obj)
```
支持：

- Map
- Set
- Date
- RegExp
- ArrayBuffer


## Map / WeakMap

### Map

特点：

- key 可以是任意类型
- 按插入顺序遍历
- size 属性
- 高性能


| 对比     | Object          | Map  |
| ------ | --------------- | ---- |
| key 类型 | string / symbol | 任意   |
| 遍历顺序   | 不稳定             | 插入顺序 |
| size   | 需要计算            | size |
| 性能     | 较差              | 更好   |

### WeakMap

WeakMap 的 key：只能是对象
并且：弱引用

当 key 对象被 GC：WeakMap 自动删除。

典型用途:

避免内存泄漏：DOM 绑定数据：

```javascript
const map = new WeakMap()

map.set(domNode, data)
```
DOM 被销毁，自动GC。



## 经典题

### 为什么 Proxy 推荐配合 Reflect？

- 保持默认行为
- 防止递归调用
- 返回值更规范
- 语义更清晰

### Proxy 和 Object.defineProperty 的区别？

| 对比   | defineProperty | Proxy |
| ---- | -------------- | ----- |
| 监听对象 | 已存在属性          | 整个对象  |
| 新增属性 | 监听不到           | 可以    |
| 删除属性 | 监听不到           | 可以    |
| 数组变化 | 很复杂            | 可以    |
| 性能   | 初始化成本高         | 更好    |


所以：

Vue2 → defineProperty
Vue3 → Proxy



### 手写深拷贝


```javascript
function deepClone(obj, map = new WeakMap()) {
  if (typeof obj !== "object" || obj === null) {
    return obj
  }

  if (map.has(obj)) {
    return map.get(obj)
  }

  const clone = Array.isArray(obj) ? [] : {}

  map.set(obj, clone)

  for (let key in obj) {
    clone[key] = deepClone(obj[key], map)
  }

  return clone
}
```



### 下面代码有什么问题？

```javascript
const proxy = new Proxy(obj, {
  set(target, key, value) {
    target[key] = value
     // 缺少 return true,否则 strict mode 报错
  }
})
```

### WeakMap 为什么不可遍历？

答案：

因为 key 是弱引用。

GC 随时可能删除 key。

如果允许遍历：

就无法保证一致性。

### Map 为什么比 Object 更适合做 HashMap？

答案：

1 key 类型不限
2 有 size
3 插入顺序稳定
4 性能更好


### 实现一个 带缓存的函数

```javascript
function memo(fn) {
  const cache = new Map()

  return function(arg) {
    if (cache.has(arg)) {
      return cache.get(arg)
    }

    const result = fn(arg)

    cache.set(arg, result)

    return result
  }
}
```

### 为什么 WeakMap 可以避免内存泄漏？

WeakMap 的 key 是弱引用（weak reference），不会阻止对象被垃圾回收。

只要对象在程序中没有“强引用”
GC 就可以回收它
即使它还在 WeakMap 里

而普通 Map 会形成 强引用，导致对象无法被回收，从而可能产生 内存泄漏。

下面代码会不会内存泄漏？

```javascript
const cache = new Map()

function process(obj) {
  if (!cache.has(obj)) {
    cache.set(obj, heavyCompute(obj))
  }

  return cache.get(obj)
}
```
可能泄漏, 因为 map 持有 obj。
